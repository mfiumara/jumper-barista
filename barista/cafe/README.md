# Cafe scene (Act 2, milestone A1)

Simulation only. Nothing here implies that the real robot has done any of it.

`cafe_bar` is the scene the Act 2 motion chain and film run in: a warm wooden bar with the
accepted M4 brew station on it, a kettle and cup stack as dressing, back-bar shelving, two
pendant lamps and an off-camera entrance door with a brass chime. It is registered in
`scenes/__init__.py` and generated by `scenes/cafe_bar.py` from
`barista/cafe/cafe_dimensions.json` (schema `jumper-barista-cafe/1`).

## Frame and route

The origin is on the bar top at Jumper's start slot, z is up, the bar top is z = 0 and the bar
runs along +X. The customer (the camera, with no 3D human) is on the -Y side looking +Y.

| Item | Value |
|---|---|
| `start_slot` | (0, 0), yaw -90 deg (faces the customer) |
| `turn` | +90 deg in place, to yaw 0 (faces +X) |
| `walk` | (0, 0) -> (0.36, 0) -> `pre_align` (0.72, 0) -> `pour_start` (0.80, 0) |
| `pour_start_pose` | x 0.80, y 0.0, yaw 0, base z 0.10847 m: the accepted M4 `base_start` plus the station offset |
| `d_walk` | 0.80 m |
| `dance_area` | disc of radius 0.34 m about the start slot: the measured footprint of every existing dance and of the in-place flat jump (dance_crab limited to its first 60 s; its full 236 s routine wanders to 0.58 m) |
| `door_chime` | site at (-2.12, -1.58, 1.12) m, above the door in the -X wall (off-camera for `customer_pov`) |
| `customer_pov` | camera at (0, -0.95, 0.35) m, looking at (0, 0, 0.12) m, fovy 50 deg |

The back-counter ledge, `h_step` and `back_counter_slot` were dropped with the story change of
`e6765ea`. The jump is the existing flat jump, in place, inside `dance_area`.

## How the brew station is copied

- The server, V60 and pitcher bodies, the hero/overhead cameras and the counter slab come from
  the hash-checked `scenes/coffee_bar.scene/scene.xml`. They are copied **verbatim** (the same
  XML text) into one `<frame name="brew_station" pos="0.818725 -0.095488 0">`. None of it passes
  through `MjSpec.to_xml`, because that rounds to six significant digits.
- The accepted counter slab (1.20 x 0.80 x 0.04 m) stays in place under the station. It is the
  declared ground, so it becomes the task's `terrain`, and it is made invisible. The bar is
  completed by three coplanar invisible collision extensions and one wooden visual top 0.3 mm
  below the collision surface. This is not cosmetic. When the station was first placed on a
  single 2.20 x 0.95 x 0.05 m bar box, the replay changed: box-vs-mesh contact moved the carried
  grasp from 9.45 mm to 10.71 mm (the gate is 10 mm). With the accepted slab moved by the same
  offset, the replay reproduced 9.45 mm.
- Additions to the brewer: `v60_coffee_bed` is a static, collidable 32 mm coffee-grounds disc
  whose top is 1.5 mm below the accepted `coffee_bed_target` plane. Its `v60_` name puts it into
  every M4 brewer gate. The visual-only V60 cues (`dripper_shell`, `dripper_flange`,
  `dripper_handle_*`) hang on a separate static body and use no `server_` or `v60_` token, so
  M4's brewer set is the accepted one plus the bed.
- The compiled offset is `(0.818725, -0.095488, 0.002)`. The accepted package is attached with
  its standing-slot site (z = 0.002 m) at the origin, while the cafe is attached at its authored
  origin.

## Evidence scripts (native:cpu, offscreen)

Every script writes JSON next to its PNGs.

```bash
python barista/cafe/settle_and_render.py --out out/cafe/settle        # A1-1 settle, A1-5 renders
python barista/cafe/footprints.py --out out/cafe/footprints           # dances, jump, turn, walk in the cafe
python barista/cafe/route_check.py --footprints out/cafe/footprints --out out/cafe/route  # A1-2 + plot
python barista/cafe/run_m4_transfer.py --out out/cafe/m4_transfer     # A1-3 accepted M4, rigidly moved
python -m pytest tests/test_barista_cafe.py
```

`run_m4_transfer.py` runs the unmodified `barista/verification/run_m4.py` with its one scene
lookup redirected to `cafe_bar`, on a copy of the accepted trajectory whose three world-frame
positions are translated. Every M4 gate therefore runs unchanged. Because of its hard-coded
label, `run_m4.py`'s own `summary.json` says `scene: coffee_bar`; `transfer_summary.json`
records the cafe.

## Known limitations

- **The V60 cone is not 60 degrees.** The accepted collision dripper (76 mm rim, 24 mm outlet,
  ribs from 5 mm to 85 mm) has an included angle of about 34 degrees. A true 60-degree visual
  cone at that rim would have to be either shorter than the accepted ribs or wider than the
  collision geometry, and would then hide real clearances. The visual shell therefore follows
  the accepted ribs. Changing the dripper geometry is a decision for the supervisor, since it
  changes the accepted M4 scene.
- Route clearance uses 2D XY convex hulls of all of Jumper's collision geometry, which is
  conservative. The last segment (`pre_align` -> `pour_start`) is the accepted M4 grasp approach,
  so the pitcher is close by design. There the transfer replay is the gate.
- The walking evidence holds the existing `jumper.posture` policy at constant commands. The
  continuous chain (dance -> chime -> jump -> turn -> walk -> align -> pour) is A4's job.
- Licence audit: there are no third-party assets. All geometry is MJCF primitives authored by
  this project or copied from the accepted project scene. The wood texture is generated in code
  (`scenes/cafe_bar.py::_wood_png`, fixed seed), and the floor uses MuJoCo's built-in checker.
  `barista/SOURCES.md` already covers project-authored primitive scenes, so nothing new is
  recorded there.
